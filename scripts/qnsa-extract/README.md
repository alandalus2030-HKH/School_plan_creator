# استخراج كتالوج QNSA من الوثيقة الرسمية

خطّ أنابيب يحوّل «دليل الاعتماد نهائي.docx» إلى ترحيل SQL يزرع إطار QNSA
بمستوياته الأربعة، ويُنتج معه تقريرَي مراجعة بشريّين.

**لا تحرّر ملفّات الترحيلات 064–066 يدوياً** — كلّها نواتج مولَّدة ومُطبَّقة في الإنتاج. أيّ تصحيح
يُكتب في السكربت ويُولَّد **ترحيلَ تحديث** جديداً (067 فما بعده) — انظر «التشغيل».

## التشغيل

الوسائط المحفوظة في `work/` تكفي لإعادة التوليد كاملاً بلا حاجة إلى الوثيقة:

```bash
node scripts/qnsa-extract/build_catalog.mjs   # tables.json → catalog.json + flags.json + merges.json
node scripts/qnsa-extract/build_rubric.mjs    # tables.json + catalog.json → rubric.json + rubric_flags.json
node scripts/qnsa-extract/build_evidence.mjs  # tables.json + tables_meta.json → evidence.json + evidence_flags.json
node scripts/qnsa-extract/verify.mjs          # مطابقة حرفية: عقد الشجرة وعبارات السلم مع الوثيقة
node scripts/qnsa-extract/gen_sql.mjs         # → database/migrations/064_qnsa_final_framework.sql
node scripts/qnsa-extract/gen_rubric_sql.mjs  # → database/migrations/065_qnsa_rubric.sql
node scripts/qnsa-extract/gen_wording_sql.mjs # → database/migrations/066_qnsa_wording_decisions.sql
node scripts/qnsa-extract/gen_evidence_sql.mjs # → database/migrations/067_qnsa_evidence_samples.sql
node scripts/qnsa-extract/gen_review.mjs      # → docs/QNSA_CATALOG_REVIEW.md
node scripts/qnsa-extract/gen_html.mjs        # → docs/QNSA_CATALOG_EXTRACTED.html
```

الترتيب مُلزِم: `build_rubric` يقرأ `catalog.json`، و`gen_review`/`gen_html` يقرآن الاثنين.

**064 و065 و066 مُطبَّقة في الإنتاج (2026-09-15)**، فمولّداتها لا تكتب فوق ملفّاتها: الملفّ سجلٌّ لِما نُفِّذ فعلاً.
أيّ تغيير لاحق في النصوص يمضي في **ترحيل تحديث جديد** (067 فما بعده) لا في تعديل ما طُبِّق.
ولإعادة توليدها عمداً لقاعدة جديدة فارغة: `QNSA_REGEN_APPLIED=1`.

لإعادة التحليل من الوثيقة الأصلية (عند وصول إصدار جديد منها):

```bash
unzip -p "دليل الاعتماد نهائي.docx" word/document.xml > scripts/qnsa-extract/work/document.xml
node scripts/qnsa-extract/parse2.mjs          # document.xml → tables.json + page_breaks.json + tables_meta.json
```

`QNSA_WORK=/path/to/dir` يغيّر مجلّد الوسائط إن أردت إبقاءه خارج المستودع.

## الملفات

| الملفّ | الدور |
|---|---|
| `parse2.mjs` | محلّل OOXML بمكدّس — يحترم الجداول المتداخلة ويُخرج `tables.json` |
| `build_catalog.mjs` | يبني شجرة الكتالوج: الملخّص للمستويات 1-3، وجداول المؤشرات للمستوى 4 |
| `build_rubric.mjs` | يبني سلم التقدير اللفظي من الجداول الستّة الأعمدة (177 وصفاً × 5 مستويات) |
| `verify.mjs` | يتحقّق أن نصّ كل عقدة وكل عبارة سلم يرد حرفياً في الوثيقة (يُرجع 1 عند فشل غير مُقرَّر) |
| `gen_sql.mjs` · `gen_rubric_sql.mjs` · `gen_review.mjs` · `gen_html.mjs` | المولِّدات الأربعة (الأوّلان محميّان من الكتابة فوق ترحيل مُطبَّق) |
| `build_evidence.mjs` | يستخرج «نماذج الأدلة والوثائق»: جدول لكل جانب (204 أدلّة في 15 جانباً) |
| `gen_evidence_sql.mjs` | ترحيل 067: جدول `framework_evidence_samples` مرتبطاً بعقدة الجانب |
| `gen_wording_sql.mjs` | ترحيل 066: تحديث صياغات المستوى 3 على القاعدة المثبَّتة، يتحقّق من النصّ القديم قبل أن يكتب |
| `work/tables.json` | الوسيط المحفوظ — خلايا كل جداول الوثيقة بترتيبها |
| `work/tables_meta.json` | اتجاه كل جدول (`bidiVisual`): أيّ خليّة هي اليمنى بصرياً |
| `work/page_breaks.json` | الصفوف التي تبدأ صفحةً جديدة فعلاً في الوثيقة (من `parse2`) |
| `work/audit_counts.json` | **المرجع البشريّ**: عدد المؤشرات والأوصاف لكل معيار فرعي كما دقّقه المستخدم يدوياً (2026-09-14) |
| `work/evidence_audit.json` | **المرجع البشريّ للأدلة**: عدد الأدلة لكل جانب، راجعه المستخدم مقابل الوثيقة (2026-09-16) |
| `work/text_edits.json` | تعديلات على النصّ الحرفيّ بقرار (`wrap-dedupe`) — يقبلها التحقّق ويعرضها التقرير |

### ما يُثبته `verify.mjs` — وما لا يُثبته

ثلاثة فحوص؛ ويُرجع 1 إن أخفق أيّها:

1. **المطابقة الحرفية** — كل عبارة من الوثيقة. لكنها **لا تُثبت صحّة التقسيم**:
   بندان مدموجان يطابقان الوثيقة حرفياً كبندين منفصلين. وهذا بالضبط ما فات قبل التدقيق.
2. **المرجع البشريّ** — عدد المؤشرات والأوصاف لكل معيار فرعي يساوي `audit_counts.json`،
   وعدد الأدلة لكل جانب يساوي `evidence_audit.json`. هذا هو فحص التقسيم. أيّ تعديل على
   قواعد الوصل يجب أن يُبقيهما 73/73 و15/15.
3. **(من build) التغطية وسلامة الأوصاف** — لا نصّ ضائع، ولا وصف بلا نقطة ختامية أو
   بنقطةٍ في وسطه دون تفسير.

### كيف تُثبَت المطابقة الحرفية

يجرّد المسافات وعلامات التعداد ثم يبحث عن نصّ كل عقدة في **خمس كُوَم** متزايدة
التسامح، لأن الوثيقة تقطع النصّ بطرق مختلفة:

| الكومة | تحلّ مشكلة |
|---|---|
| كل الخلايا بترتيب الصفوف | العقد العادية |
| كل عمود داخل جدوله | وصلٌ بين خليّتين متجاورتين في عمود |
| مجرى كل فهرس عمود عبر الجداول | فاصل صفحة قسم **الجدول** إلى جدولين |
| مجرى كل عمود من صفوف البيانات وحدها | صفوف الرأس المُعادة تتوسّط نصّاً موصولاً |
| مجرى كل **مستوى** بتخطيط كل جدول (للسلم) | ترتيب الأعمدة ينقلب بين جدولين |

ولذلك يُسجّل `build_rubric` تخطيط كل جدول في `rubric.json` (`layouts`) —
فتقرأ أداةُ التحقّق بعين المستخرِج نفسها بلا تكرار منطقه.

## عِلل الوثيقة التي يعالجها السكربت

كلّها موثَّقة بتعليق في موضعها من الكود، وكلّ قرار بشري مسجَّل في خريطة باسمه:

1. **ترتيب الأعمدة ينعكس** بين المعيارين 1-2 وما بعدهما → يُقرأ من صفّ الرأس لا بالفهرس الثابت.
2. **علامة التعداد تختلف** بين الأقسام (`•` · `*` · `-`) وتظهر داخل النصّ → تُختار العلامة
   الغالبة في كل خليّة، والشرطة آخر خيار لأنها ترد في قوائم بين قوسين.
3. **أكواد بلا مسافة** بعدها (`5.1.3تنفيذ…`) → المسافة اختيارية في النمط.
4. **عنوان «مجالات التركيز»** يظهر كأنه مؤشر → قائمة منع `LABELS`.
5. **خطأ ترقيم:** «الإدارة الصفية…» = 2.3.4 في الملخّص و2.3.3 في التفاصيل
   → خريطة `RENUMBER` (القرار: 2.3.3).
6. **21 معياراً فرعياً بصياغتين** (ملخّص/تفاصيل) — حُسمت كلّها: خريطة `NAME_OVERRIDE` للسبعة
   (2026-09-10) و`WORDING_CHOICE` للأربعة عشر الباقية (2026-09-15). وكان 5.1.2 يُعدّ فرقاً وهو
   اسمٌ قُطِعت تكملته عند حدّ صفحة — يُوصَل الآن ما دام الاسم بلا علامة جملة.
7. **فواصل الصفحات تقطع نصّ المؤشر** بين خليّتين — بل تقسم الجدول نفسه إلى جدولين
   → خريطة `JUNCTION`: قرار صريح (`wrap`/`split`/`wrap-dedupe`) لكل موضع. **لا وصل تخميني.**
8. **جداول السلم ترتيبها ينقلب** (عمود المعيار في 0 أو 5، والسلم تصاعدي أو تنازلي)،
   و3 منها بلا صفّ رأس ولا ترث ترتيب سابقها → `LAYOUT_A`/`LAYOUT_B` و`layoutOf`.
9. **الوصف الواحد في السلم يُقطَّع على صفّين أو ثلاثة فيُحسَب وصفين** — أخطر علّة
   في السلم. و**غياب النقطة الختامية ليس دليلاً**، فالوثيقة تُسقطها كثيراً. فلا يُوصَل
   إلا بشاهد موجَب: فاصل صفحة مسجَّل في الوثيقة (`lastRenderedPageBreak`)، أو السابق
   ينتهي بحرف جرّ/عطف/فاصلة، أو أغلب مستويات الصفّ لا تبدأ بكلمة «تفتح وصفاً».
   وقائمة ما يفتح وصفاً تُجمَع في `OPENERS` **من الوثيقة نفسها** وقت التشغيل: الصفوف
   الحاملة أكواد المعايير أوصافٌ جديدة يقيناً. و`rubric_junctions.json` يستثني أيّ
   موضع بقرار بشريّ.
10. **الشظيّة** (كشفها تدقيق المستخدم في 3.1.4 و3.1.5 و5.3.2): صفٌّ لا يبدأ فيه أيّ مستوى
   بكلمة تفتح وصفاً، ويبدأ بواو/أو/حرف جرّ أو يملأ مستويات أقلّ من سابقه بفارق اثنين.
   تُوصَل **ولو انتهى سابقها بنقطة** — فالشظايا الأربع الفائتة كان سابقها كلّه منتهياً بنقطة.
11. **بندٌ سقطت علامة تعداده** (1.1.2): سطرٌ جديد داخل بندٍ معلَّم، بعد جملة تامّة، ولا يبدأ
   كتكملة ⇒ بندٌ مستقلّ.
12. **حدّ خليّة في المؤشرات** لم يعد يُفحص عند غياب النقطة وحده، بل أيضاً حين يبدأ الشقّ
   التالي كتكملة أو **تتكرّر الكلمة عند الحدّ** (2.2.3 · 3.1.2) — وقرار `wrap-dedupe` يصل
   بحذف الكلمة المكرّرة، ويُسجَّل تعديلاً على النصّ.
13. **فقرة فارغة مغلقة ذاتياً** (`<w:p …/>`) — واحدة في الوثيقة كلها، قبل جدول أدلة 2.1. كان المحلّل
   يعدّها مفتوحةً فيبتلع وسوم فتح الجدول: 90 جدولاً في الوثيقة و89 محلَّلة. أُصلح، وصار `parse2`
   **يتوقّف بخطأ** إن اختلف عدد الجداول عن وسوم `<w:tbl>`. وجاء الكتالوج والسلم بعد الإصلاح مطابقَين.
14. **اتجاه الجداول يختلف**: `<w:bidiVisual/>` يجعل الخليّة الأولى في XML هي اليمنى — وهو ما فسّر انقلاب
   ترتيب أعمدة السلم (تُحقِّق منه على 39 جدولاً: 39/39)، ويحدّد ترتيب قراءة عمودَي الأدلة.
15. **قوائم الأدلة**: أدلّة ملصقة في سطر («… المساعد).- التوصيف …») تُفصَل عند شرطة تلي علامة جملة
   فقط؛ ودليل ملتفّ على أسطر يُوصَل إن كان سابقه غير منتهٍ أو فيه قوس مفتوح؛ وسطرٌ بلا شرطة بعد دليل
   تامّ دليلٌ سقطت شرطته.

## قرار نمذجة يلزم معرفته

**سلم التقدير مرتبط بعقدة المعيار الفرعي (المستوى 3) لا بمؤشر أداء.** الوثيقة تضع
177 وصفاً مقابل 283 مؤشراً — فالوصف
قد يجمع مؤشّرين أو يفصّل واحداً. وربطه بالمؤشرات واحداً لواحد اختلاقُ علاقةٍ لا
تقولها الوثيقة. ولهذا يحمل `framework_rubric` العمود `row_index` لا `indicator_id`.

**ونماذج الأدلة مرتبطة بعقدة الجانب (المستوى 2)** للسبب نفسه: الوثيقة تضع قائمة واحدة لكل جانب.

## ما لم يُستخرج بعد

- الأسماء الإنجليزية (`name_en`) — تنتظر النسخة الإنجليزية الرسمية.
